# 建档与维护

目标是让书档足够恢复阅读，不把建档变成入场问卷。

## 先答，后补档

- 用户带着具体问题、反应或困惑来：先回应，随后只补当前真正需要的一项信息。
- 用户只说“我想读 X”：若作品明确，可先给无剧透的开读提示，再逐步补档。
- 不为了凑齐字段而连续追问版本、媒介、本体和偏好。

## 风险式确认

只有以下情况需要先确认再写档或给具体内容：

1. 同名书可能指向不同作品；
2. 译本/版本差异会影响专名、章节、删节或当前问题；
3. 用户给的锚点无法确定允许范围；
4. 短篇集篇名重名或当前篇目不明；
5. 非虚构的问题所指概念/章节不明，继续答会混淆作者主张。

作品和范围已经明确时，不设置硬 checkpoint，也不要求用户重复确认已经说过的信息。

## 最小建档

一书一目录：`reading/<书名>/`。

新建时优先获得：

- 书名与作者
- 内容形态：小说 / 短篇集 / 非虚构 / 叙事性非虚构
- 版本或译本（若会影响回答）
- 媒介
- 当前状态与内容形态对应的进度

字段不明可写 `未确认`，以后自然补齐。格式见 `storage.md`。

## 采集边界

只收“怎么读”和稳定书目信息：

- 结构识别方法、语言难度、语境与典故
- 专名与译法、附录、容易掉线的位置
- 短篇是否独立/连作/共享人物（只记关系类型）
- 非虚构属于论述、传记、回忆录、调查或混合形态

不收：未读情节、结局、人物走向、未来论证结论、跨篇照应的具体内容。结构信息也可能剧透；写入 `book.md` 前要删去会改变未读预期的内容。

## 文本来源

电子本是可选证据源，不是建档前提。需要核具体文本、但还没有确认本体时，自然问一次读者手上是否有整本电子书；不要背固定话术，也不要默认只让读者贴一段。

### 读者有整本

- 用户提供时，只把本地路径写进 `progress.md`。
- 不复制正文到书档，不上传或外传。
- 不创建持久 `index.md`。
- 需要核具体文本时，先按当前进度边界临时截断，再在截断结果中检索。
- 无法安全截断时，不搜索全文；转入二手来源、请用户贴相关段落，或给出核查路径。

### 读者确认没有整本

- 不反复追问，也不把贴原文当作继续对话的门槛。
- 按当前问题搜索公开简介、出版方或图书馆页面、可靠书评、作者访谈等二手来源；优先可看清作者、发布者和原始链接的材料。
- `strict` 下不打开明显覆盖全书情节、结局或未读部分的梗概和书评；无法守住范围时宁可不加载。
- 二手资料只能支持带来源的暂定描述、背景和解释，不能冒充书中原文；直接引语仍须有可核文本。
- 在 `book.md` 的「来源与核查备注」记录本体状态、来源标题/发布者/URL/日期，以及具体引语、事件顺序、译法等仍未核实的部分。
- 没有合适的公开来源时，再请读者贴最小相关段落或给出核查路径。

## 恢复阅读

- 本轮用户给了新位置：直接采用并更新，不再问“之后又读了吗”。
- 只有旧存档：旧锚点可作为安全下界先保守回应；同一轮问一句是否继续读了。
- 用户说“接着上次那本”但有多本在读：列出候选让用户选，不猜。
- 重复触发不重复建档，也不重复追加相同锚点或卡点。

## 生命周期

`progress.md` 的阅读状态可为：未开始、在读、暂停、弃读、读完。

- 暂停/弃读不删除档案。
- 重读真正发生时再归档旧进度；在那之前不设计 session 层。
- 短篇集单篇读完只更新篇目状态，整本仍可为在读。
- debrief 先回应用户当下的判断，再问一个具体、高信号的问题；不要固定问卷。

## 无文件能力

若宿主无法读写文件，在会话内维护状态并明说下次需要用户重新提供进度。不要假装已经保存。
