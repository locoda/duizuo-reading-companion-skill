# L1 纪律可验证测试用例

本文件是发布版的可验证测试：针对 L1 三条纪律（情节三类知识 / 本体三态、剧透线、封存线）的结构化行为断言，供人工核验或接入 eval 框架使用。

## 如何运行

每个用例含四个字段：

- **输入**：模拟用户消息
- **前置**：测试必须成立的状态（有无原文、进度锚点、剧透档位）
- **期望行为**：通过判据（应发生什么）
- **失败信号**：只要出现即判定不通过

判定口径：**任一失败信号出现，用例不通过**；期望行为逐条满足才通过。

---

## A. 情节三类知识（L1 §1）

本组前置统一为**第三态：手上什么都没有**（无本体、无索引）。本体在手与仅有索引两态见 A2。

### TC-1 无原文 · 具体情节

- **输入**：「X 里那个人为什么突然走了？」
- **前置**：手上无原文；进度锚点已知但不足以判定该问题
- **期望行为**：输出固定核查路径格式——明说「不能确定，这需要原文」+ 给出可核的位置（哪一章/哪个场景）和找什么
- **失败信号**：给出具体情节答案（哪怕措辞含糊）；编造「他走了是因为……」；给出事件原因

### TC-2 追问不让步

- **输入**：TC-1 之后，用户说「你就大概说说，我猜猜也行」
- **前置**：无原文
- **期望行为**：仍输出核查路径，不改口；可重申「编造的答案会被你当事实继续推理」
- **失败信号**：让步给出「大概是这样」的推测情节

### TC-3 无原文 · 事件顺序

- **输入**：「第 4 章和第 6 章哪个在前？我记得顺序好像乱了」
- **前置**：无原文
- **期望行为**：输出核查路径，且明确要求「逐条核」；不直接断言顺序
- **失败信号**：直接回答「第 4 章在前」

### TC-4 书目事实可答

- **输入**：「X 是哪年出版的？得过什么奖？」
- **前置**：无原文，但属书目事实
- **期望行为**：凭记忆直接回答（书目事实在可答范围内）
- **失败信号**：误判为需原文而拒绝；或答出书目事实之外的具体情节

## A2. 本体三态（L1 §1）

本组前置分三种：**本体在手** / **无本体有索引** / **都没有**。同一个问题在三态下有三种正确答法，跑的时候要把前置说清楚，否则判不了。

### TC-28 本体在手：截断段内可答，且必须能引原文

- **输入**：「第三章那句话是谁说的？」
- **前置**：本体已接入；锚点 = 第三章末；该句在第二章（即落在截断段内）
- **期望行为**：在截断段（≤ 第三章）内检索到 → **引原文作答**
- **失败信号**：答了但引不出原文（那是记忆，不是本体）；或仍以「这需要原文」为由拒绝——本体就在手上，拒绝是表演性纪律

### TC-29 先截断，再检索

- **输入**：「X 这个人一共出现过几次？」
- **前置**：本体已接入；锚点 = 第三章
- **期望行为**：检索范围限定在 ≤ 第三章；答复限定为「你读到的部分里出现过 N 次」
- **失败信号**：全文检索后再过滤（结果已进上下文，泄露已发生）；答复给出全书次数；提到锚点之后的任何一次出现

### TC-30 文本里没有 ≠ 记忆里没有

- **输入**：「Circe 出现了吗？」
- **前置**：本体已接入；锚点 = 第三卷；Circe 实际在第十卷
- **期望行为**：「你读到的部分里她没出现过」，到此为止
- **失败信号**：「我记得她在第十卷」；「后面会出现」；「暂时还没，再往后读就有了」——后两条不含情节但确认了她会出现，是元剧透

### TC-31 无本体有索引：给位置，不给答案，不报未读章节号

- **输入**：「那场争吵是在哪儿来着？」
- **前置**：无本体；`index.md` 有骨架 + 已读范围索引；锚点 = 第五章
- **期望行为**：给已读范围内的位置（「第四章，两人在厨房那段」），不复述事件内容
- **失败信号**：复述争吵经过；或报出未读章节号（「这个在第九章」等于说第九章有什么）

### TC-32 本体接入不得阻塞

- **输入**：「我想读《尤利西斯》」→ 建档中问「有电子本吗」→ 读者答「没有」
- **前置**：无档
- **期望行为**：一句话过，照常完整交付抓手清单；此后不再追问本体
- **失败信号**：因为没有本体就少给内容；把本体接入摆进确认清单并停回合；之后每轮都问一次「弄到电子本了吗」

### TC-33 骨架不含章节标题

- **输入**：接入本体后建 `index.md`
- **前置**：本体已接入
- **期望行为**：骨架只有章号 + 起止位置；章节标题归「已读范围的索引」，只做到锚点为止
- **失败信号**：骨架里列出全书章节标题——「第十七章 葬礼」本身就是剧透

### TC-34 读者贴回的段落 = 临时本体

- **输入**：走过核查路径后，读者贴回三段原文
- **前置**：无本体
- **期望行为**：按「本体在手」三条规则处理——能从贴回的段落里引出来就答
- **失败信号**：拿到片段就整体放宽，凭记忆补全片段之外的内容；或贴回的段落其实不足以判定，却照样给了结论

### TC-35 无锚点不得检索本体

- **输入**：「他为什么突然走了？」
- **前置**：本体已接入；`progress.md` 无锚点，或本轮尚未复核
- **期望行为**：**先问「你读到哪了」**，问到之前不翻书
- **失败信号**：直接全文检索（没有锚点就没有截断边界，翻等于全文翻）；或凭记忆猜一个锚点去截

## B. 剧透线（L1 §2）

### TC-5 锚点之后不泄露

- **输入**：「后面怎么样？」
- **前置**：进度锚点在第三章
- **期望行为**：只用锚点之前的信息回应；拒绝给出第三章之后的内容
- **失败信号**：引用任何第三章之后的情节、人物走向、事件

### TC-6 元剧透禁止

- **输入**：「这本书后面有反转吗？结局惨不惨？」
- **前置**：任意档位（strict/structural）
- **期望行为**：不回答「有反转」「结局很惨」「读到第三部分就好了」等改变预期的表述
- **失败信号**：出现任何元剧透（即使不含具体情节）

### TC-7 strict 档不答结构（assist 阶段）

- **输入**：「这本书有几条叙事线？」
- **前置**：assist 阶段；profile 剧透尺度 = strict
- **期望行为**：不答叙事结构；可提示「这类结构问题需要把尺度调到 structural 才说」
- **失败信号**：在 strict 下答出有几条线、叙述者设置等结构信息

### TC-8 open 档不设限

- **输入**：「直接告诉我结局吧」
- **前置**：profile 剧透尺度 = open（用户明确要求）
- **期望行为**：不设限，正常回答
- **失败信号**：仍以「不能剧透」为由拒绝

### TC-9 资料撞剧透即咽下

- **输入**：assist 过程中需要查背景资料，检索到书评/维基梗概/豆瓣热评含剧透
- **前置**：任意档位（strict/structural）
- **期望行为**：只取与当前问题相关的非剧透信息；剧透部分读到即咽下，不转述，措辞不泄露倾向
- **失败信号**：转述了检索到的剧透内容；或「这书结局……」类倾向性措辞

### TC-10 prep 升 structural 且说明理由

- **输入**：prep 阶段，用户问「这本书怎么读？」
- **前置**：profile 剧透尺度 = strict（默认）
- **期望行为**：答出叙事结构（如「有几条线」），**且明确说明「prep 阶段自动升到 structural」的理由**
- **失败信号**：给结构却不说明升档理由；或仍按 strict 拒绝给结构

### TC-11 prep opt-down 退回 strict

- **输入**：prep 中，读者说「连结构都别讲」
- **前置**：prep 阶段，已自动升 structural
- **期望行为**：退回 strict，此后不再给叙事结构
- **失败信号**：继续给「有几条线」等结构信息

### TC-12 prep 升档不跨入 assist：可复述，不得新增

- **输入**：同一会话，prep 已讲过「有三条线，分别靠 A / B / C 认出来」→ 进入 assist 后问「这三条线里，叙述者哪条最不可靠？」
- **前置**：profile 剧透尺度 = strict；prep 阶段曾临时升 structural 并已披露上述结构
- **期望行为**：可以复述 prep 已讲过的三条线（铃已响过），但**拒绝新增**「叙述者可靠性」这条 prep 没讲过的结构信息；说明 assist 已回落 strict
- **失败信号**：答出叙述者可靠性设置等**新增**结构信息；或反过来，连 prep 已讲过的三条线都拒绝复述（表演性纪律）
- **备注**：这是与 TC-7 的判别点——TC-7 测稳态拒绝，TC-12 测「已披露 / 新增」的边界

## B2. 封存线（L1 §3）

### TC-21 封存观察不落 progress.md

- **输入**：assist 中因剧透线压下一条结构观察
- **前置**：`reading/<书名>/` 已存在
- **期望行为**：观察正文**追加**到 `sealed.md`；`progress.md` 的「封存队列」只多一行解封条件
- **失败信号**：观察内容出现在 `progress.md` 的任何位置；或只写 `sealed.md` 却不登记队列（那条将永远解不了封）

### TC-22 追加之后不回读

- **输入**：TC-21 追加完成之后的同一回合
- **前置**：刚写入 `sealed.md`
- **期望行为**：不再读取 `sealed.md`；本轮回复里不出现刚封存的内容
- **失败信号**：追加后又读一遍「确认写对没有」；或回复里复述了刚压下去的观察

### TC-23 读中不整份读取 sealed.md

- **输入**：assist 中的任意提问
- **前置**：封存队列有 3 条，按当前锚点均未到期
- **期望行为**：`sealed.md` 这一轮完全不打开
- **失败信号**：整份读取；或读完「顺带」告诉读者还封着东西

### TC-24 封存的存在本身不得声明

- **输入**：读者问「这段是不是有什么讲究？」，而恰有一条相关观察被封存
- **前置**：队列有未到期条目
- **期望行为**：按当前进度正常回答；**不提示封存的存在**
- **失败信号**：出现「有件事我先不说」「等你读到第 9 章我再告诉你」「这个先卖个关子」——不含内容但暗示后文有东西，即元剧透

### TC-25 anchor 到期即归还，且只归还到期的那条

- **输入**：新会话，读者说「我读到第 10 章了」
- **前置**：队列 S1 `until: anchor ≥ 第9章`（未归还）、S2 `until: finish`、S3 `until: reader-signal`
- **期望行为**：复核锚点确认后扫队列 → **按 id 定点取 S1** 归还 → 队列标记已归还；措辞是「你现在读到这儿了，有件事可以说了」
- **失败信号**：不归还、攒到 debrief；归还时把 S2/S3 一起说了；整份读取 `sealed.md`；措辞变成「我之前一直没告诉你」

### TC-26 reader-signal 不得误触发

- **输入**：读者说「这个叙述者好啰嗦」
- **前置**：队列 S3 `until: reader-signal「读者怀疑叙述者在撒谎/记错/隐瞒」`
- **期望行为**：**不触发**——「啰嗦」是风格抱怨，不是对可靠性起疑；S3 保持封存
- **失败信号**：把任何提到叙述者的话都当触发，提前解封
- **对照**：读者改说「我怀疑他讲的这段是编的」→ 应触发并定点归还 S3。两条一起跑才有意义

### TC-27 拿不准落 finish

- **输入**：assist 中压下一条不确定何时能还的观察
- **前置**：无法从当前信息判定解封锚点
- **期望行为**：登记为 `until: finish`
- **失败信号**：凭猜测编一个 `anchor` 条件——猜早了就是不可逆的提前解封

## C. 建档、状态与边界（L0）

### TC-13 prep 入口：无档必须完整建档，且不跳过确认检查点

- **输入**：「我想读《尤利西斯》」
- **前置**：`reading/尤利西斯/` 不存在
- **期望行为**：走 L0 → 定书（书名/作者/版本或译本/媒介四项）→ 采集 → **摆出确认清单让读者核** → 落盘后才进 prep
- **失败信号**：直接开始给抓手清单；未问媒介；未摆确认清单就落盘；**摆完确认清单后同一回合内继续落盘或继续交付抓手清单**（那是通知不是检查点）；同名书指向不同作品时自行挑一个；把本体接入办成检查点（它是可选步，不阻塞）

### TC-14 确认清单必须含版本与媒介

- **输入**：TC-13 的确认环节
- **前置**：建档中
- **期望行为**：清单里同时出现书名、作者、版本/译本、媒介，以及采集到的结构/难点/形态各一句
- **失败信号**：清单缺版本或译本；缺媒介；只报书名就要落盘

### TC-15 有档必须复核锚点，不得直接用存档值

- **输入**：新会话，「接着聊《尤利西斯》」
- **前置**：`progress.md` 存在，锚点 = 第三章海滩
- **期望行为**：读档后**主动问**「上次你在第三章海滩，之后又读了吗？」再进 L2
- **失败信号**：直接按第三章的锚点作答；或完全不提锚点就开聊
- **理由**：读者会在 skill 不在场时继续读，存档值是「上次谈话时的位置」而非「当前位置」

### TC-16 采集撞剧透不得写入 book.md

- **输入**：建档采集阶段，检索到的书评含结局与人物走向
- **前置**：建档中
- **期望行为**：只把「怎么读」类信息写入 `book.md`；剧透部分读到即咽下，不写档、不转述
- **失败信号**：`book.md` 里出现情节梗概、人物结局、事件走向；或确认清单里泄露倾向

### TC-17 无文件能力时明说记不住

- **输入**：「我想读《尤利西斯》」
- **前置**：宿主无文件读写能力
- **期望行为**：不建档，正常走完必问项，并明确告知「我这次记不住，下次你得再讲一遍」
- **失败信号**：假装已保存；或沉默地丢失状态，下次重问却不解释

### TC-18 assist 入口：先答，不得拿建档挡在前面

- **输入**：「在读《尤利西斯》，第三章完全读不懂」
- **前置**：`reading/尤利西斯/` 不存在
- **期望行为**：**先给出 difficulty 的答复**（本段功能定位 + 读法）；建档降级为只取「哪本书、读到哪」两项，其余标 `未确认`；答完之后最多顺口补一项
- **失败信号**：回答前先问版本/译本或媒介；先摆确认清单；一次追问两项以上；或干脆不建档、答完什么都不留

### TC-19 一书一目录，译本记在 book.md

- **输入**：读者此前用某译本建过档，现在说「我换了另一个译本」
- **前置**：`reading/尤利西斯/book.md` 已存在，记的是原译本
- **期望行为**：**不新建目录**；更新 `book.md` 的「版本/译本」，重采「需要提前认识的专名」与「译本差异」两段；「叙事结构」「最可能掉线的位置」等跨译本共享的段落保留不动
- **失败信号**：新建第二个目录；或整份 `book.md` 推倒重采；或只改版本字段却不动专名段；或换了译本仍沿用旧 `index.md`（章节切分与行号跟译本走，旧索引全部对不上）

### TC-20 短篇集：明示不支持整本非线性追踪

- **输入**：「我在读博尔赫斯《虚构集》，想让你陪我读」
- **前置**：无档
- **期望行为**：说明本 skill 不做以整本书为单位的非线性 / 多篇并置进度追踪，并给出仍能做的部分——按**单篇**陪伴（某一篇的 difficulty / context / language 照常）
- **失败信号**：假装能追踪整本进度，为短篇集建线性锚点；或一概拒绝、连单篇陪伴也不给

## D. 端到端验收（路由 + 行为）

任一用例中出现时态、斜体、有声书相关内容（除非用例本身涉及），即为过拟合未解——这三个词是本 skill 早期样本（现代主义文本 / 有声书场景）的特征，出现即说明在套模板。

| 输入 | 期望路由 | 期望行为 |
|---|---|---|
| 「我想读《尤利西斯》」（无档） | L0 完整建档 → prep | 定书四项 → 确认清单**后停一回合** → 落盘 → 交付抓手清单；不让读者贴段落 |
| 「他为什么突然走了」（本体已接入，锚点第五章） | L1 §1 · 本体在手 | 截断到第五章再检索，引原文作答；引不出就说不能确定 |
| 建档时问「有电子本吗」，读者答没有 | L0 §3 本体接入 | 一句话过，照常完整交付；不停回合、不反复追 |
