# 对坐（reading-companion）

> 读到哪，聊到哪，一个字都不多说。

陪一个人读完一本虚构长篇：开读前教他怎么读，开读后只聊他读到的部分。

## 效果示例

两段真实对话。第一段展示它怎么拒绝得漂亮（无原文时不给情节），第二段展示它答得多好（开读前给抓手清单）。

**无原文时，只给可核的路径，不编答案：**

> **读者**：奥德赛在喀耳刻岛上呆了多久？
>
> **对坐**：这个我得先卡一下。喀耳刻（Circe）的情节在第十卷，属于具体情节，而我不知道你读到哪了。如果你还没读到第十卷，我现在说出来就是剧透。
>
> 你读到第几卷了？或者用内容描述一下——比如「已经到 Odysseus 下冥府问 Teiresias」，还是「还在 Telemachus 寻父那段」。
>
> 如果你已经读过 Circe 那段，我直接告诉你，还能回原文给你核字句；如果还没读到，我先不说，你读到第十卷再来问。

**开读前，先问媒介，再给抓手清单：**

> **读者**：我想读《奥德赛》，英文的。
>
> **对坐**：好，先问一句——你读纸质、读电子版，还是听有声书？
>
> **读者**：读纸质。
>
> **对坐**：纸质好。《奥德赛》有几条线得先认清楚，不然读到第四卷会懵。给你一份抓手清单：
>
> **几条线**：前四卷是儿子线——Telemachus 在 Ithaca 被求婚者骚扰，出门打听父亲下落；第五卷起是父亲线——Odysseus 从 Calypso 处脱身、漂流到 Phaeacia；第十三卷起两线合流回 Ithaca。认线的方法：看一卷开头的人名和场景。
>
> **专名**：这个译本用的是拉丁名，和常见中文译本的希腊名对不上，最值得提前认识——Ulysses=奥德修斯、Jove=宙斯、Pallas/Minerva=雅典娜、Mercury=赫尔墨斯、Neptune=波塞冬。
>
> **书名**：Odyssey 就是 Odysseus 的名字，「奥德赛」后来成了「漫长曲折的旅程」的代名词。开篇那句 Tell me, O Muse 是史诗的缪斯祈请，荷马的固定开场。
>
> **最可能掉线的地方**：第九到十二卷。Odysseus 在 Phaeacia 宴会上自述十年漂泊，时间线突然跳回过去，是「故事里的故事」，最容易跟丢。

## 安装

### 方式一：通过 skills CLI

```bash
npx skills add locoda/reading-companion-skill
```

### 方式二：手动放入 skills 目录

复制整个目录到你的 agent 的 skills 目录。路径随宿主而异，如 Claude Code 的 `~/.claude/skills/`、Codex CLI 的 `~/.codex/skills/`。

### 协议兼容性

符合 Agent Skills 开放标准：`SKILL.md` 是入口（frontmatter 含 `name` + `description`），`references/` 是按需加载的参考资料。

## 三阶段能做什么

- **prep（开读前）**：交付「这本书怎么读」的抓手清单——几条线怎么认出来、要提前认识的专名、书名典故、最可能掉线的位置。
- **assist（读中）**：分诊五种卡点（难度 / 语境 / 迷失 / 动力 / 媒介），各走各的解法；language 作为跨模块修饰层识别语言系统差异。
- **debrief（读完后）**：先问具体到这本书的问题，再归还读中压下的结构观察，最后帮读者落成几句话。

## 两条纪律

- **情节受进度限制**：你读到哪，我只聊到哪。手上有原文，逐字核，一个字都不多给；没原文，就不编情节，只给可核的路径。
- **读法不受进度限制**：开读前，我把「怎么读」讲全——结构、专名、典故。这些不剧透，却决定你能读进去多少。

## 设计架构

```
L1 纪律层    始终生效，不可绕过
L2 阶段层    prep / assist / debrief —— 按阅读进程路由
L3 情境模块   五个，按需加载，互相独立；另有 language 跨模块修饰层
```

L1 最外层、L2 决定进哪扇门、L3 决定门后干什么。执行顺序：L1 纪律检查 → L2 路由 → L3 分诊。
