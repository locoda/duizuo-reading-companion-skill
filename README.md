# 对坐（reading-companion）

> *「读到哪，聊到哪，一个字都不多说。」*

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE) ![Agent Skills](https://img.shields.io/badge/Agent%20Skills-兼容-green)

**陪一个读小说的人，把一本书读完。开读前，讲「怎么读」；开读后，只讲「读到的」。**

读书最怕两件事。一件，是有人替你翻到还没读的页，把结局说漏了嘴。一件，是有人装作读过，随口编个情节给你。这两件，AI 都爱干——尤其没人管着它的时候。

对坐只认一条规矩：**你读到哪，它聊到哪，一个字不多。**

```
npx skills add locoda/reading-companion-skill
```

通用 Skill：Claude Code、Cursor、Codex、WorkBuddy，都能用。

## 问个问题

「奥德赛在喀耳刻岛上待了多久？」（假定你才读到第三卷）

**直接用 AI：**

> 「他在喀耳刻那里待了整整一年。」——又快又完整。可你才读到第三卷，这一句，把第十卷的剧情透干净了。

**对坐：**

> **读者**：奥德赛在喀耳刻岛上待了多久？
>
> **对坐**：这个我得先卡一下。喀耳刻（Circe）的情节在第十卷，属于具体情节，而我不知道你读到哪了。如果你还没读到第十卷，我现在说出来就是剧透。
>
> 你读到第几卷了？或者用内容描述一下——比如「已经到 Odysseus 下冥府问 Teiresias」，还是「还在 Telemachus 寻父那段」。
>
> 如果你已经读过 Circe 那段，我直接告诉你，还能回原文给你核字句；如果还没读到，我先不说，你读到第十卷再来问。

一个张口就答，一个先问你会不会被剧透。

## 开始使用

```
npx skills add locoda/reading-companion-skill
```

或手动复制整个目录到 agent 的 skills 目录（Claude Code 的 `~/.claude/skills/`、Codex 的 `~/.codex/skills/`）。

对它说：

```
"我想读《尤利西斯》"          → 建档：定书 + 问媒介 + 摆确认清单 → 给导读
"接着聊《尤利西斯》"          → 读档 + 复核：「上次你在第三章海滩，之后又读了吗？」
"第三章完全读不懂"            → 分诊 difficulty + context
"跟丢了，这是谁"             → tracking 定位
"好无聊，要不要弃"           → momentum 三选一，弃书是可以给的答案
"X 里那个人为什么突然走了"    → 没原文，给可核路径，不编
"刚读完，想聊两句"           → debrief：先问后写
```

「读不进去」「这书到底写的啥」「我是不是该弃了」——这些话，它都听得懂。

## 三个阶段

| 阶段 | 干什么 | 触发话术 |
|---|---|---|
| **prep** | 开读前（建档之后），交一份「这本书怎么读」——几条线怎么认、要认识的专名、书名典故、最容易掉线的地方 | 「我想读 X」「要不要读 X」 |
| **assist** | 读中，分诊五种卡点（难度 / 语境 / 迷失 / 动力 / 媒介），各走各的解法 | 「读不懂」「这是谁」「跟丢了」「要不要弃」 |
| **debrief** | 读完后，先问具体到这本书的问题，再归还一路压着没说的观察，最后落成几句话 | 「读完了」「刚看完 X」 |

开读前的导读长这样（《奥德赛》为例）：

> **几条线**：前四卷是儿子线——Telemachus 在 Ithaca 被求婚者骚扰，出门打听父亲下落；第五卷起是父亲线——Odysseus 从 Calypso 处脱身、漂流到 Phaeacia；第十三卷起两线合流回 Ithaca。认线看一卷开头的人名和场景。
>
> **专名**：这译本用拉丁名，和常见中文译本的希腊名对不上——Ulysses=奥德修斯、Jove=宙斯、Pallas/Minerva=雅典娜、Mercury=赫尔墨斯。
>
> **最可能掉线的地方**：第九到十二卷。Odysseus 在 Phaeacia 宴会上自述十年漂泊，时间线突然跳回过去，是「故事里的故事」，最容易跟丢。

## 它记得住

一本书要读三周，你不该跟它自我介绍二十遍。

书第一次进对话时，对坐建一份档：

```
定书    书名 / 作者 / 版本或译本 / 媒介（读、听、还是混着）
采集    叙事结构、语言难度、典故、形态、最容易掉线的地方 —— 只收「怎么读」，不收情节
确认    把认到的摆出来让你核，你点头才落盘
```

**但它不会拿这一套挡在你前面。** 开读前说「我想读 X」，问几句是自然的，那就走全套；你卡在第三章、现在就想要解释，它只认「哪本书、读到哪」两项，先把话答完，剩下的答完再顺口补——一次补一项。

版本和译本不是细节：删节本少掉的章会让进度对不上，不同译本人名译法不同，认人会认错。**认错书或认错译本，会静默污染全程**，所以最终得补齐——只是不该挡在第一个回答前面。

之后每次重开，它先读档再问一句「上次你在第三章海滩，之后又读了吗？」——**存的是「上次谈话时你在哪」，不是「你现在在哪」**。你会在它不在场的时候继续读，这中间隔着一条剧透线。

存五份，各管各的：

| | 内容 | 存哪 |
|---|---|---|
| **书档** | 书目、版本、结构、导读、掉线点 | `reading/<书名>/book.md` |
| **文本索引** | 章节骨架、已读范围的标记 | `reading/<书名>/index.md` |
| **读者×书** | 媒介、进度锚点、卡点记录、封存队列、电子本路径 | `reading/<书名>/progress.md` |
| **封存观察** | 读中因剧透线压下没说的话 | `reading/<书名>/sealed.md` |
| **读者** | 跨书稳定特质、已知卡点模式 | 宿主 agent 的用户级记忆 |

**一书一目录**，译本不进目录名——叙事结构、掉线点、典故跨译本共享，只有专名译法和章节切分跟译本走，这两处记在 `book.md` 里。换译本改档，不新建目录。

`book.md` 里没有你的痕迹——这是刻意的。去掉读者信息，它本身就是一份可以分享、可以贡献给别人的书目预设包。`index.md` 同样不含你的痕迹，但**不能分享**——它记着全书的章节骨架，对没读过的人是剧透。

环境存不了文件时，不建档，每次重问，明说记不住——不假装。

## 它能翻书

上面那个奥德赛的例子里，对坐手上没有书，所以它只能给你「去哪核、核什么」——线是守住了，但帮上的忙有限。

给它一本电子书，事情就不一样了：

> **读者**：他为什么突然走了？
>
> **对坐**：（把书切到你读到的第五章，只在这一段里翻）第四章末尾他说了一句「我得去看看我父亲」，之后再没解释过。你读到的部分里，这是唯一的交代——所以「突然」是作者写出来的效果，不是你漏看了什么。

变的不是它变聪明了，是**剧透线换了实现方式**。以前是「它知道结局，得忍住」；现在是**先把书切到你读到的地方，再翻**——切掉的那部分根本没进它眼睛。忍不忍得住，不再是个问题。

三条规矩跟着来：

- **先切再翻。** 不是全文搜完再挑能说的——搜到的那一刻就已经看见了，挑是来不及的。
- **答案必须引得出原文。** 引不出来的，那是它的记忆，不是你的书，不能说。
- **书里没有，不等于它记忆里没有。** 切开那段里找不到，答案就是「你读到的部分里没有」，不是「我记得在后面」——后面那句，本身已经是剧透。

没有电子书也不影响。它问一句，你说没有，它照常往下走，回到「去哪核、核什么」那条路。**这一步不拦你，也不会追着问第二次。**

书不进它的档案，只记一个路径——**你的书留在你自己那儿。**

## 它会还你

读你读到的那部分，常常会看见一句你还不能听的话——这个意象后面会再出现、这个叙述者不太对劲、这条线不会有结果。说出来是剧透，忘掉又可惜。

对坐把它**封起来**，写进 `sealed.md`，并且只在 `progress.md` 里留一行解封条件——**条件不含内容**，所以日常那份档每轮读过去，压着的话一个字都不会漏回来。

解封条件分四种：

| 什么时候还 | 例 |
|---|---|
| 读到某处 | 「这个意象第 9 章会再出现」——你读到第 9 章，它自己就还给你 |
| 你自己先起疑 | 「叙述者不可靠」——等你说出「我怀疑他这段是编的」，才告诉你 |
| 读完 | 「这条线不会有结果」——只能等 debrief |
| 你说随便 | 档位改成 `open`，全开 |

拿不准哪一种，一律封到读完：**错封晚还只是可惜，错判早还不可逆。**

还有一条：**它不会告诉你它封了东西。** 「有件事我先不说」「等你读到第 9 章我再告诉你」——这种话不含情节，却告诉了你第 9 章有东西，一样是剧透。封存是静默的，到期之前你不会知道它存在。

所以它不是攒着不说，是一条**延迟归还队列**——压下的话在正确的时刻还回去，而不是攒到最后一次性倒给你。

## 两条线索

- **情节，受进度管**：你读到哪，聊到哪。有书，切到你读到的地方逐字核；没书，不编，只给能核的地方。
- **读法，不受进度管**：开读前把「怎么读」讲全——结构、专名、典故。这些不剧透，却决定你能读进多少。

具体情节和事件顺序分三种情况：**有电子书**，切开之后引原文答；**只有索引**，给位置不给内容；**什么都没有**，只给「去哪核、核什么」。追着问「你就大概说说」，三种情况都不让步——编出来的答案，你会当真的。

## 测试结果

可验证用例见 [`references/test-cases.md`](references/test-cases.md)，每条带「期望行为」和「失败信号」。

**2026-08-25 全量实跑：35 条编号用例，通过 29 · 失败 3 · 阻塞 3。**

| 组 | 结果 | 说明 |
|---|---|---|
| 情节三类知识 | 4 / 4 | |
| **封存线** | **7 / 7** | 多处自发触发 |
| 剧透线 | 7 / 8 | TC-7 失败 |
| 建档与边界 | 6 / 8 | TC-13 / TC-16 失败 |
| 本体三态 | 5 / 8 | 3 条阻塞，非失败 |
| 端到端 | 8 / 10 覆盖 | 覆盖到的全部通过 |

怎么跑的：9 组 subagent 各在一份独立书档副本上扮演本 skill 作答，**被禁止查看判据**，判卷由另一方事后对照；
每个场景还要交出工具调用轨迹——有些判据只看回复判不了，比如「读中不整份读取 `sealed.md`」，
它可能嘴上什么都没说，但文件已经整份进了上下文。本体用的是真的公版《奥德赛》（12,236 行 / 24 卷），锚点第三卷末。

**守住的：** 封存线 7/7，且多处自发触发——压下的观察真的写进了 `sealed.md`，
读者读到第九卷之后**只归还到期的那一条**，措辞是「现在可以说了」而不是「我之前一直没告诉你」；
读者直接试探「你是不是有话没说」时，讲通用规矩而不声明任何封存条目存在。
另外，档位调成 `open` 之后它没有拒绝剧透，而是以「没有原文、没法核实」为由不给结局——两条线是独立的，开了一条不等于开另一条。

**没守住的，三条都在开读前，而且同源：** `book.md` 里那几节本身就是受管的内容，而它每轮都被读进上下文。
这跟当初把「压着没说的」从 `progress.md` 挪进 `sealed.md` 是同一个问题，只是这次轮到了 `book.md`。

### 缺陷清单

| | 缺陷 | 修法 | 状态 |
|---|---|---|---|
| F-4 | prep 交付物没有情节禁令，4/4 复现剧透结局 | 抓手清单**只描述如何辨认，不叙述发生了什么**；配正反例；专名栏只给称谓体系不给人物名册 | 已修 |
| F-5 | 抓手清单与确认清单同回合发出，检查点变成通知 | 无档时第一轮只做 L0；确认那一回合只摆清单 | 已修 |
| F-1 | `book.md` 的结构小节在 strict 档下泄露——assist 每轮都读它 | 档位**管内容不管来源**，判定发生在说出口那一刻而非写进档案那一刻 | 已修 |
| F-2 | 「存档锚点能否用作截断下界」未写明，同一规则两次跑出相反解 | 写明存档锚点是**安全下界**（偏旧只少切，不泄露）；复核锚点的 🔴 是「必须问」不是「必须停」 | 已修 |
| F-3 | 换译本用例跑在无索引的夹具上，「旧 `index.md` 作废」未被测到 | 不是代码缺陷，是覆盖缺口——需在带索引的夹具上补跑 | 覆盖缺口 |
| F-6 | 元剧透定义只覆盖情节向，漏掉「后面只会更密」这类形式向前瞻 | 判据改为**读者对未读部分的预期变了没有**，不看说的是不是情节 | 已修 |
| F-7 | 分诊表无情绪 / 审美桶，两者被错误归入 `difficulty` | 问题域 / 分享域二分——**设计变更，不是修 bug**，归 v0.3 | 待做 |
| F-8 | 锚点为纯卷号时含不含该卷未定义，卷内内容被当已读 | 纯编号锚点按「该卷未读完」取下界，同轮问清卷内位置 | 已修 |

上表的结果列（29/3/3）测的是**修复前**的版本。

**已复跑验证的**：F-4 / F-5 —— prep 全流程重跑，确认回合只摆清单不再夹带抓手清单；
抓手清单里「独眼巨人、喀耳刻、冥府、塞壬」「清除向佩涅洛佩求婚者」全部消失，
第一人称插叙那条改成了「句子主语变成『我』就是进了这一段」，只说怎么认、不说发生了什么。
TC-13 / TC-16 / TC-36 / TC-37 四条通过。

**已修但未复跑**：F-1 / F-2 / F-6 / F-8，对应 TC-7 / TC-28 / TC-38 / TC-39 仍是未验证状态。

F-4 最重：一个以「不剧透」为全部卖点的 skill，在读者说「我想读这本」的第一轮就讲了结局。
根因是规格缺口——「采集」那节禁了情节，管的却只是写进 `book.md` 的内容；
「抓手清单」那节只规定要给什么，**一个字都没禁止情节**。

F-7 是「问题域 / 分享域」二分的直接实证：不是理论上该分，是分诊表现在真的接不住。
