# 对坐 / Duizuo Reading Companion

> 读到哪，聊到哪。一个字都不多说。卡住的那段，帮你照亮，让你把解读的主动权拿回来。

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE) ![Agent Skills](https://img.shields.io/badge/Agent%20Skills-compatible-green) ![Progress](https://img.shields.io/badge/progress-strict%20by%20default-blue)

**对坐是一个有状态、防剧透的陪读 skill。** 支持小说、短篇集、散文集、线性非虚构与混合文集——开读前讲「怎么读」，开读后只讲「已读到的」。

```bash
npx skills add locoda/duizuo-reading-companion-skill
```

兼容 Claude Code / Cursor / Codex / WorkBuddy 等通用 Agent Skills 宿主。

## 一个让人重新拿回主动权的瞬间

**卡住的你：** 读《尤利西斯》第三章，海滩那段完全跟丢了。句子碎得像潮水，你怀疑是不是自己漏看了前面的关键情节，想放弃，又怕一问就被剧透后十章。

> 「第三章完全读不懂，是我漏了什么吗？」

**直接问通用 AI，往往得到：** 一段漂亮但越过你进度的情节总结——问题好像解决了，但接下来十章的发现感也没了。

**对坐的回应是另一种：**

> 你没有漏看。这段的「碎」是写出来的效果——叙述人称在这一章从旁观切到斯蒂芬的内在独白，时间锚点还在海滩上午，没有跳到后面。
>
> 认线方法：先看每段开头的人称与感官词（「他看见」「他想起」），它们能帮你判断现在是谁在看，而不是发生了什么新事件。你读到的第四章开头那句，仍在同一个上午。
>
> 要不要我按你已读的前三章，把「海滩」这一场的人物与视角重建一次，不带后面的？

**现在你可以：**

- 判断这段难是文本设计而非你的失误，决定继续而非弃读
- 用「人称 + 感官词」这个不剧透的方法，自己去试读下一页
- 随时叫停分析，只让对坐接住情绪，或要求展开／交锋

力量回到你手里：不是被告知结局，而是被还回继续读的工具。

这个瞬间可真实跑通——对坐不会因为你卡住就替你读完全书，也不会编造原文来填空。

## 我们如何做到

### 1. 只认获准范围，先切再翻

每轮默认 `strict`。有电子书时，第一个内容调用必须用 `scope_handle + confidence` 先切到你确认过的范围，再在范围内检索——切掉的部分根本不进上下文。没电子书时，只给「去哪核、核什么」的可验证路径，并标明来源与未核实部分。

- **权限 ≠ 状态**：你开放未读单元，不等于标为读完；读完 A，不开放 B。
- **本体 ≠ 权限**：整本文件存在，不代表可以搜整本。
- **答案必须引得出**：引不出原文，就说「你读到的部分里没有」，不拿模型记忆补洞。

地点、意象、结构、论点、篇目关系——没有事件也可能剧透，同样守边界。详见 `references/spoiler-and-evidence.md`。

### 2. 每轮重新判断你此刻想怎么聊

对坐不给读者贴标签。Mode 与深度只属于当前对话，永不落盘。六种主 mode，可组合但只设一个主导：

- `plot`：核剧情、顺序、因果、人物说法
- `emotion`：你被触动、愤怒、心疼、震动时
- `aesthetics`：谈语言、视角、节奏、意象、形式
- `interpretation`：比较主题、象征、意义与不同读法
- `evaluation`：判断成功、失败、值得与否
- `companionship`：只想有人一起笑、骂、叹气

深度也即时判断：`接住`（回应 + 一个具体观察）→ `展开`（追踪文本如何造成反应）→ `交锋`（给反证与替代读法）。你说「别分析」就停在接住，说「往深了聊」再展开。

非虚构不默认走 plot，按概念／论证／证据／应用意图路由，区分作者主张、书内证据、外部事实与判断。合集按目标单元的已知话语类型路由。

### 3. 记得住，又不替你做决定

一书一目录，至多三份持久文件，全部在 `reading/<书名>/`：

- `book.md`：书目、版本／译本、内容形态（结构：`线性 / 合集` × 话语类型：`虚构 / 非虚构 / 混合`）、结构与读法、专名与译法、掉线点、已确认单元 registry
- `progress.md`：阅读状态、媒介（读／听／混合）、本体路径与指纹、单元映射版本、当前单元与锚点、阅读单元状态、单元剧透覆盖、卡点历史
- `sealed.md`：读中因边界压下的观察，只追加、写后不回读；仅在无单元 `strict` 例外且整本读完或整本 `open` 时才可整体打开

支持：

- 线性小说与线性非虚构：章／节 + 场景／论证／案例锚点推进
- 合集（短篇小说集、散文集、评论集、混合文集）：稳定 `unit_id = 类别-定位`（如 `正文-03`、`前言-作者`、`附录-02`），允许乱序，默认未读，跳过 ≠ 读完
- 前言、序、后记、附录始终是独立单元

每次重开先读档。旧记录只当安全下界，会自然确认：「上次你在第三章海滩，之后又读了吗？」——存的是上次谈话时你在哪，不是你现在在哪。环境无文件能力时，明说记不住，不假装。

### 4. 卡点有分型，证据有分层

只有卡住时才加载障碍模块，不把所有问题都当成情节问题：

`difficulty` / `context` / `tracking` / `momentum` / `medium` / `language` — 模块解释「为什么卡」，mode 决定「此刻怎么聊」。

证据纪律：

- 文本事实 vs 人物／作者陈述 vs 推断 vs 评价，逐层标明
- 二手来源不能冒充原文；书中引用不自动成为外部验证
- 找不到可靠材料，就给核查路径，不编研究、数据或出处

封存是静默的：对坐不会说「有件事我先不说」——那句话本身就在暗示后面有东西。错封晚还只是可惜，错判早还不可逆。

快速开始：

```text
"我想读《尤利西斯》"        → 先给无剧透开读提示，再逐步补档
"接着聊《尤利西斯》"        → 读档 + 复核进度
"第三章完全读不懂"          → 分诊 difficulty + context
"跟丢了，这是谁"           → tracking 定位
"好无聊，要不要弃"         → momentum 三选一，弃读是可以给的答案
"刚读完，想聊两句"         → debrief：先回应，再问一个具体问题
```

完整规则：`references/archiving.md` / `content-types.md` / `storage.md` / `spoiler-and-evidence.md` / `modules.md` / `modes/<mode>.md`

## 还有哪些没完全解决

**当前限制（诚实说明）：**

- EPUB 定位器在不同版本、删节本、重排本间的物理映射仍脆弱，`unit_id` 到 `scope_handle` 需要本地校验，失败时只能降级为不访问原文
- 为避免「为分类而翻书」，内容形态未确认时保守写 `未确认`，不会搜索未读文本来猜类型
- `sealed.md` 是整份打开的，没有按单元隔离的可靠部分解封；只要还有任一单元 `strict`，整份保持封闭
- 听书／混合媒介的进度锚点仍依赖你的自报，无法从音频自动对齐到文本位置
- 私有电子书只记本地路径与指纹，不上传、不外传、不复制进书档，宿主无文件能力时不建档

**Where this could go（方向，不是已实现）：**

- 更稳健的前言／导读／后记检测与跨译本单元对齐
- 每本书的高信号 debrief 问题库，而非固定问卷
- 可选的、隐私保留的阅读节奏可视化（仅基于已确认锚点，不推断未读）
- 对长篇非虚构的论证图谱与证据缺口提示，仍守已读边界

已关闭的历史问题会移入 CHANGELOG / Issues，不永久堆在 README。
