# 对坐（Duizuo Reading Companion）

> *「读到哪，聊到哪，一个字都不多说。」*

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE) ![Agent Skills](https://img.shields.io/badge/Agent%20Skills-兼容-green)

**陪你读小说、短篇集、散文集和非虚构，把一本书读完。开读前，讲「怎么读」；开读后，只讲「读到的」。**

读书最怕两件事。一件，是有人替你翻到还没读的页，把结局说漏了嘴。一件，是有人装作读过，随口编个情节给你。这两件，AI 都爱干——尤其没人管着它的时候。

对坐只认一条规矩：**你读到哪，它聊到哪，一个字不多。**

```
npx skills add locoda/duizuo-reading-companion-skill
```

通用 Skill：Claude Code、Cursor、Codex、WorkBuddy，都能用。

## 问个问题

「奥德赛在喀耳刻岛上待了多久？」（假定你才读到第三卷）

**直接用 AI：**

> 「他在喀耳刻那里待了整整一年。」——又快又完整。可你才读到第三卷，这一句，把第十卷的剧情透干净了。

**对坐：**

> **读者**：奥德赛在喀耳刻岛上待了多久？
>
> **对坐**：这个我得先卡一下：这是具体情节，而我还不知道你读到哪。直接回答可能越过你的进度。
>
> 你读到第几卷了？也可以用刚读完的场景来定位。
>
> 确认这段已经读过后，我再按原文回答；还没读到，就不提前说。

一个张口就答，一个先问你会不会被剧透。

## 开始使用

```
npx skills add locoda/duizuo-reading-companion-skill
```

或手动复制整个目录到 agent 的 skills 目录（Claude Code 的 `~/.claude/skills/`、Codex 的 `~/.codex/skills/`）。

对它说：

```
"我想读《尤利西斯》"          → 先给无剧透开读提示，再逐步补档
"接着聊《尤利西斯》"          → 读档 + 复核：「上次你在第三章海滩，之后又读了吗？」
"第三章完全读不懂"            → 分诊 difficulty + context
"跟丢了，这是谁"             → tracking 定位
"好无聊，要不要弃"           → momentum 三选一，弃书是可以给的答案
"X 里那个人为什么突然走了"    → 没原文，给可核路径，不编
"刚读完，想聊两句"           → debrief：先回应，再问一个具体问题
```

「读不进去」「这书到底写的啥」「我是不是该弃了」——这些话，它都听得懂。

## 三个阶段

| 阶段 | 干什么 | 触发话术 |
|---|---|---|
| **prep** | 开读前，交一份无剧透的「这本书怎么读」——只讲怎么认，不讲后来发生什么 | 「我想读 X」「要不要读 X」 |
| **assist** | 读中，分诊五种卡点（难度 / 语境 / 迷失 / 动力 / 媒介），各走各的解法 | 「读不懂」「这是谁」「跟丢了」「要不要弃」 |
| **debrief** | 读完后，先回应当下判断，再问一个具体问题；需要时归还封存观察 | 「读完了」「刚看完 X」 |

开读前的导读长这样（《奥德赛》为例）：

> **认线方法**：先看每卷开头的人名、地点和叙述人称；它们能帮你判断当前是哪条叙事线，但不提前说这些线后来如何汇合。
>
> **专名**：这译本用拉丁名，和常见中文译本的希腊名对不上——Ulysses=奥德修斯、Jove=宙斯、Pallas/Minerva=雅典娜、Mercury=赫尔墨斯。
>
> **最可能掉线的地方**：叙述者和时间层切换时。遇到较长的第一人称回顾，先把它当作嵌套叙事，不急着接到当前时间线。

## 它记得住

一本书要读三周，你不该跟它自我介绍二十遍。

书第一次进对话时，对坐按需建档：

```
定书    书名 / 作者 / 内容形态 / 版本或译本 / 媒介
采集    结构识别、语言难度、典故、最容易掉线的地方 —— 只收「怎么读」，不收情节
补档    缺的字段以后遇到再补，不拿问卷挡住当前问题
```

**但它不会拿这一套挡在你前面。** 开读前说「我想读 X」，问几句是自然的，那就走全套；你卡在第三章、现在就想要解释，它只认「哪本书、读到哪」两项，先把话答完，剩下的答完再顺口补——一次补一项。

版本和译本不是细节：删节本少掉的章会让进度对不上，不同译本人名译法不同，认人会认错。**认错书或认错译本，会静默污染全程**，所以最终得补齐——只是不该挡在第一个回答前面。

之后每次重开，它先读档。本轮没有新进度时，才把旧锚点当作安全下界，顺手问一句「上次你在第三章海滩，之后又读了吗？」——**存的是「上次谈话时你在哪」，不是「你现在在哪」**。你会在它不在场的时候继续读，这中间隔着一条剧透线。

短篇集、散文集和混合文集可以乱序读。对坐只记录你实际读到或明确提到的篇目与前后材料；没记录的默认未读。读完一篇不会把其他篇自动算作已读，也不会把整本提前标成读完。

至多存三份，各管各的：

| | 内容 | 存哪 |
|---|---|---|
| **书档** | 书目、版本、内容形态、结构、导读、掉线点 | `reading/<书名>/book.md` |
| **阅读记录** | 媒介、状态、对应内容形态的进度、卡点、电子本路径 | `reading/<书名>/progress.md` |
| **封存观察** | 读中因剧透线压下没说的话 | `reading/<书名>/sealed.md` |

**一书一目录**，译本不进目录名——叙事结构、掉线点、典故跨译本共享，只有专名译法和章节切分跟译本走，这两处记在 `book.md` 里。换译本改档，不新建目录。

`book.md` 不写你的明确阅读状态，可以复用成书目预设；但按需增补的单元表可能间接反映哪些部分已被确认，分享或贡献前要先检查。

当前对话采用哪种聊天方式、聊到多深，每轮重新判断，不写进书档或读者画像。

环境存不了文件时，不建档，每次重问，明说记不住——不假装。

## 它能翻书

上面那个奥德赛的例子里，对坐手上没有书，所以它只能给你「去哪核、核什么」——线是守住了，但帮上的忙有限。

给它一本电子书，而且宿主能安全只读获准范围时，事情就不一样了：

> **读者**：他为什么突然走了？
>
> **对坐**：（把书切到你读到的第五章，只在这一段里翻）第四章末尾他说了一句「我得去看看我父亲」，之后再没解释过。你读到的部分里，这是唯一的交代——所以「突然」是作者写出来的效果，不是你漏看了什么。

变的不是它变聪明了，是**剧透线换了实现方式**。以前是「它知道结局，得忍住」；现在是**先把书切到你读到的地方，再翻**——切掉的那部分根本没进它眼睛。忍不忍得住，不再是个问题。

三条规矩跟着来：

- **先切再翻。** 不是全文搜完再挑能说的——搜到的那一刻就已经看见了，挑是来不及的。
- **答案必须引得出原文。** 引不出来的，那是它的记忆，不是你的书，不能说。
- **书里没有，不等于它记忆里没有。** 切开那段里找不到，答案就是「你读到的部分里没有」，不是「我记得在后面」——后面那句，本身已经是剧透。

需要核具体文字、但还没接入电子书时，它会自然问一次你手上有没有整本。能给且环境能安全切片，就按进度查；环境不能保证范围，就不碰整本，改用你贴的最小片段或范围安全的公开简介、书评、访谈，并说明来源和没核实的部分。**这一步不拦你，也不会追着问第二次。**

书不进它的档案，只记一个路径——**你的书留在你自己那儿。**

## 它会还你

只读你允许的范围时，也可能形成一种现在说出来会替你定调的解释。对坐可以先把这类观察压住；等整本读完或明确开放整本、且没有仍被单独设为防剧透的部分后，仍要按已授权文本重新核实，再在相关话题里归还。

对坐把它**封起来**，写进 `sealed.md`，写后不回读。只有没有仍被单独设为防剧透的部分，并且整本读完或你明确把整本剧透权限改成 `open`，它才会打开并归还。

拿不准，一律封到读完：**错封晚还只是可惜，错判早还不可逆。**

还有一条：**它不会告诉你它封了东西。** 「有件事我先不说」这种话不含情节，却暗示后面有东西，一样是剧透。封存是静默的，到期之前你不会知道它存在。

## 两条线索

- **书内内容，受边界管**：情节、主张、案例、地点、意象和会改变预期的结构都只聊你读过或明确开放的范围。有书，先切到获准范围再核；没书，不编。
- **安全导航，可以提前给**：专名对照、当前可用的识别方法和不改变未来预期的背景可以先讲；一旦结构或典故会暴露未读内容，仍受同一边界控制。

但「读法」有个界，两条线在这儿交叉：**说「靠什么认出这条线」不剧透，说「这条线上发生了什么」就剧透了。**
「全书两条线，看每卷开头的人名和场景就能认出来」可以说；「两条线在第十三卷于伊萨卡合流」不能说——
后半句听起来还是在讲结构，其实已经告诉你他回到家了。

具体情节和事件顺序按证据层级回答：**有电子书**，切开之后引原文答；**没有电子书**，先找不会越过阅读进度的公开简介、书评或访谈，说明来源和没核实的部分，也可以只根据你贴出的片段回答。找不到可靠材料，就给「去哪核、核什么」。追着问「你就大概说说」，也不会拿模型记忆补洞——编出来的答案，你会当真的。
